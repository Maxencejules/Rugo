# Product static ELF preflight v1

Scope: the default TinyGo product lane's `sys_spawn` ET_EXEC branch, not the
historical compatibility model, kernel-image loader, or ET_DYN/PIE loader.
The parser is `kernel_rs/src/elf_static.rs`; `exec_load_app` calls that same code
with the child's `mm::as_copyout` and `mm::as_map_zeroed` callbacks.

## Accepted format

- Current-version, little-endian ELF64, `ET_EXEC`, `EM_X86_64`, 64-byte ELF header.
- 1–8 program headers, each at least 56 bytes; the entire table, including
  declared padding, must be present. Section headers are not needed for execution.
- At least one nonempty `PT_LOAD`. Every load has `p_filesz <= p_memsz`, a file
  range inside the package payload, and a non-wrapping memory range wholly in
  `[0x0140_0000, 0x017F_F000)`. The following page is reserved for spawn arguments.
- `p_align` is 0/1 or a power of two with congruent file/virtual offsets.
  Nonempty segment byte ranges cannot overlap. Disjoint segments may share a page
  and can appear in either order. BSS-only data segments are supported.
- The entrypoint belongs to a nonempty load marked `PF_X`. This checks the
  declared segment, not instruction validity or actual page permissions.
- `PT_DYNAMIC` and `PT_INTERP` are rejected for this static branch. Other non-load
  headers do not cause writes. PIE still uses the existing separate loader and
  its existing relocation/ASLR contract; this patch does not certify arbitrary
  Linux binaries, dynamic linking, or strengthen PIE validation.

ELF field meanings and alignment follow the primary
[ELF header reference](https://refspecs.linuxfoundation.org/elf/gabi4+/ch4.eheader.html)
and [program-header reference](https://refspecs.linuxfoundation.org/elf/gabi4+/ch5.pheader.html).
The bounded window, eight-header limit, no-overlap policy and unsupported static
runtime linking are Rugo product restrictions, not universal ELF requirements.

## Failure and memory contract

All ranges, segments and the entrypoint are checked before the first child-memory
callback. Overflow, truncation or a bad later segment returns `None` with no
load writes. `sys_spawn` then releases its newly created child address space and
emits `EXEC: <name> badelf`; no task has been started.

On a valid image, file bytes are copied and remaining BSS pages are ensured in a
fresh zero-initialized address space. Mapping existing pages does not erase them;
disallowing overlapping segment bytes keeps BSS independent of load order.
Allocation/copy callback failure can leave the private child partly initialized;
the existing syscall cleanup releases it. This is validation before writes,
not rollback of allocation failures, allocator-exhaustion proof, or W^X enforcement
for ELF segments. Existing dynamic-memory protection gates remain separate.

## Reproduce the evidence

Host, offline, with Python 3.9+ and installed Rust:

```sh
python tools/test_exec_static_v1.py
# Equivalent Make target:
make test-exec-static-host-v1
```

`RUSTC`/`--rustc` selects a compiler; `RUSTC_LINKER` optionally selects its host
linker. The tool records exact compiler/version/flags and test transcripts under
`out/exec-static-v1/`, compiles a `no_std` library with warnings denied, then runs
the same 20 tests at `opt-level=0` and `3`. Linux and Windows CI run this direct
gate. Tests verify independently specified bytes/BSS, shared and multiple pages,
all eight headers, entry/alignment/range rejection, callback failures, and 5,000
fixed-seed mutations. The memory callbacks are a host model: these results alone
do not prove paging, disk I/O, scheduling or boot containment.

Native Linux toolchain and QEMU (the same prerequisites as `make image-go`):

```sh
make test-exec-static-v1
```

The strict gate builds the product ISO, packages seven synthetic malformed ELFs
with genuine PKG v1 hashes, and drives the real shell's `probe`/`sys_spawn` path.
It requires seven `badelf` rejections, then actual `PAGE3: ok` from the assembled
multi-page static app and `BASESH: hello from disk` from the linked PIE app,
followed by clean shutdown. It rejects missing boot artifacts rather than skipping.
The normal full QEMU CI suite also runs this test with strict prerequisites and
uploads `out/exec-static-v1/qemu-serial.txt`. The separate host package check verifies
on-disk payload hashes so an accidental `badhash` cannot replace ELF containment.

Local Windows development may run the host gate and package check without an ISO;
pytest then reports the boot test as skipped. Such a run must not be described as
native runtime evidence. CI's real serial transcript is the boot proof; no synthetic
timing or qualification report is generated by this gate.
